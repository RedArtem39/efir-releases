# Правила для разработчиков

Кратко: автоматизировать можно только ботов, через Bot API. Всё остальное — руками в
приложении.

## Можно

- Делать ботов: аккаунт через `@bot_bot`, работа через `/api/v1` с заголовком
  `Authorization: Bot <токен>` и шлюз событий.
- Писать ботов на любом языке. На Node.js — с библиотекой `efir-bot`: её можно
  использовать, менять и распространять по лицензии MIT.
- Добавлять бота на сервер по приглашению и давать ему роли. Что он может, решают права
  этих ролей и каналов, как у людей.
- Отвечать в личку тем, кто написал боту первым.
- Хранить данные, которые нужны для работы бота (настройки, счётчики, очереди), и удалять
  их по просьбе человека.

## Нельзя

- **Автоматизировать обычный аккаунт** (селфботы): входить скриптом, брать cookie сессии,
  вызывать адреса приложения вне `/api/v1`. Эти адреса только для самого приложения, ботам
  они закрыты, и их устройство может меняться без предупреждения.
- **Обходить лимиты**: несколько ботов или токенов ради скорости, повторы без ожидания
  `retry_after`. Лимиты — в [быстром старте](bots/README.md#лимиты).
- **Спамить**: массовые сообщения, рассылки по серверам, реклама без согласия владельца
  сервера.
- **Собирать чужие данные**: выгружать историю переписки, списки участников или профили
  для чего-либо, кроме работы самого бота на этом сервере.
- **Выдавать бота за человека** или за официальные аккаунты (`@bot_bot` и подобные).
- **Изменять или разбирать приложение**, делать сторонние клиенты: это запрещает
  [лицензия](../LICENSE) (пункты 2 и 3).
- **Публиковать токен.** Токен — это пароль бота. Утёк — сразу `/token @имя_bot` в
  `@bot_bot`: старый перестанет работать.

## Если правила нарушены

Владелец сервера может удалить бота с сервера или забанить его, владелец Эфира — удалить
бота и аккаунт его создателя.

## Что меняется

Bot API (`/api/v1`) меняется с сохранением совместимости: поля добавляются, существующие
не меняют смысл. Если что-то придётся убрать, это будет описано в релизе заранее.
